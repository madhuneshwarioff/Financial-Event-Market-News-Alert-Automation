Your watchlist tells you what happened. This tells you what is about to.

Market Pulse checks the earnings calendar, the economic calendar and the newswire every morning and evening, works out which dates are close enough to matter, ranks the headlines that are actually about your positions, and sends one short brief to Telegram or your inbox. Everything below runs from a single Python command.

How a brief gets built

Five stages. Each one is a separate module with its own tests, so a broken news provider never stops the calendar half from delivering.

Pipeline

src/pipeline.py

Fetch

Three Finnhub calendar endpoints and two news feeds are pulled in parallel with exponential backoff. HTTP 429 counts as retryable, which matters on a free tier capped at sixty calls a minute. Every provider row is converted into the same two dataclasses, so adding a fourth source touches one file.

src/fetchers/

Process dates

Providers send ISO strings, unix timestamps and day-first dates in the same response. They are all parsed into real dates, moved into your timezone, labelled with a days_until count, and dropped if they fall outside the alert window. Events then sort soonest first, highest impact first within a day.

src/processing/date_processor.py

Rank and dedupe

A headline earns points for hitting your watchlist, for keyword class, and for being fresh. Anything under the threshold is dropped, syndicated copies collapse onto one normalised signature, and a SQLite table of fingerprints makes sure the same story is never sent to you twice.

src/processing/filters.py

Notify and export

Telegram gets an HTML message trimmed to the 4096-character limit; email gets a multipart message so text-only clients still read it. Channels return a result object rather than raising, so one dead channel never blocks the other. The same digest is written to JSON for the dashboard.

src/notifiers/

Why one headline makes the cut and another does not

The score is deliberately a transparent sum rather than a model, so any alert can be explained after the fact. Weights live in config.yaml.

Scoring rules

SignalWeightApplies when
Watchlist symbol+2.0the story is tagged with a symbol you follow (capped at two)
High-priority keyword+2.5earnings, acquisition, investigation, interest rate, downgrade…
Medium-priority keyword+1.0dividend, buyback, analyst, layoffs, lawsuit…
Published under 3h ago+1.5halved between three and eight hours old
Below min_scoredropnever reaches a notifier at all

A worked example

“Regulators open investigation into Tesla driver-assist claims”

  • TSLA on the watchlist+2.00
  • keyword investigation+2.50
  • keyword recall in the summary+2.50
  • published 7 hours ago+0.75
Final score7.75

Tagged negative because two lexicon words (investigation, probe) matched and none positive. Marked high importance, so it leads the brief.

Run it in four commands

The demo flag uses bundled data, so the whole pipeline works before you have signed up for anything.

Install and try it

# 1 · clone and install
git clone https://github.com/<your-username>/market-pulse.git
cd market-pulse
pip install -r requirements.txt

# 2 · run the whole pipeline on bundled data
python run.py --demo --dry-run

# 3 · add your keys, then send for real
cp .env.example .env
python run.py --test-channels
python run.py

# 4 · keep it running on a timer
python run.py --schedule

Keys you need, and what each unlocks

  • Finnhub — free tier, no card. Earnings, IPO and economic calendars plus company news. This is the only key the project really needs.
  • NewsAPI — optional second feed for broader business coverage.
  • Telegram bot token and chat id — from @BotFather and the getUpdates endpoint. Two minutes, no approval step.
  • SMTP credentials — optional. Gmail needs a 16-character app password; the account password is rejected on two-factor accounts.

Without any keys the pipeline still runs end to end on the bundled sample data, which is how the test suite and CI exercise it.
